Ini **bagian 1** dari serial implementasi **Hermes Agent** di yeremiachris.com. Di sini kita berhenti di titik yang paling realistis untuk hari pertama: **VPS sudah di-order dan statusnya checking** — belum install Hermes, belum gateway Discord. Part berikutnya baru masuk ke server: install, konfigurasi model, dan nyambungin bot.

Kalau kamu baru dengar istilah "AI agent" lewat chatbot di browser, tulisan ini sengaja pelan-pelan. Tujuannya jelas: fondasi dulu, biar langkah berikutnya tidak nebak-nebak.

## Hermes Agent itu apa, dan kenapa "self-improving"?

**Hermes Agent** adalah agent AI open source dari [Nous Research](https://github.com/NousResearch/hermes-agent) — bukan sekadar chat window di website. Agent di sini artinya program yang bisa **menjalankan alat** (baca file, jalankan perintah, jadwalkan tugas, dan sebagainya), **mengingat sesi sebelumnya**, dan **menyimpan skill** yang bisa dipakai lagi.

Yang bikin Hermes beda dari chatbot biasa adalah **loop belajar**: dari pengalaman dipakai, dia bisa membuat atau memperbaiki skill, mengingatkan dirinya untuk menyimpan hal penting, dan mencari lagi percakapan lama kalau kamu butuh konteks. Chatbot klasik? Kamu tanya, dia jawab, selesai. Tidak ada "hari ini saya belajar cara deploy ulang yang lebih aman" yang tersimpan untuk besok.

Analogi sederhana: chatbot itu resepsionis yang hanya baca FAQ. Hermes lebih mirip asisten yang punya **buku catatan + kotak perkakas** — dan buku catatannya bisa bertambah isi kalau kamu sering pakai dia untuk pekerjaan yang sama.

Hermes juga **tidak mengunci model**. Kamu bisa pakai provider apa pun yang didukung (OpenRouter, OpenAI, endpoint sendiri, dan lain-lain). Di journey ini saya pilih **DeepSeek API** — bagian stack-nya kita bahas di bawah.

## Fungsi singkat: buat apa Hermes dipakai?

Tanpa mengarang use case pribadi di luar rencana project ini, secara umum Hermes cocok kalau kamu mau:

- **Asisten yang jalan di server**, bukan di laptop yang harus nyala 24/7.
- **Satu gateway** ke banyak channel (CLI, Discord, Slack, Telegram, dan lain-lain) — nanti di serial ini **gateway-nya Discord**, bukan Telegram.
- **Otomasi terjadwal** (laporan harian, backup, audit) lewat cron bawaan.
- **Delegasi tugas** ke subagent kalau pekerjaan bisa dipecah paralel.
- **Skill yang bisa dibagikan** (standar agentskills.io) supaya tidak mulai dari nol setiap minggu.

Untuk konteks blog ini: langkah awalnya adalah menyiapkan **rumah** agent itu — VPS murah yang nanti dipakai install Hermes dan jalankan proses gateway.

## Stack yang dipilih: DeepSeek API + VPS murah

Best practice untuk percobaan pertama: **pisahkan otak dan badan**.

| Lapisan               | Pilihan                                       | Alasan singkat                                                                         |
| --------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------- |
| Model (otak)          | [DeepSeek API](https://platform.deepseek.com) | Harga kompetitif, API familiar, gampang ganti model lewat konfigurasi Hermes nanti     |
| Compute (badan)       | VPS Linux murah                               | Agent + gateway jalan terus; laptop tidak perlu hidup 24 jam                           |
| Channel (mulai nanti) | Discord                                       | Satu server/guild yang sudah dipakai tim; dokumentasi Hermes mendukung gateway Discord |

Kenapa tidak langsung serverless atau cluster GPU? Bisa — Hermes memang mendukung banyak backend. Tapi untuk **belajar sambil jalan**, VPS $5-an itu sweet spot: murah, SSH jelas, upgrade RAM/CPU tinggal ubah plan. Kalau nanti butuh Modal/Daytona, fondasi VPS tetap berguna sebagai staging atau bastion.

Yang **belum** kita lakukan di bagian 1: install `hermes-agent`, set `config.yaml`, atau pasang token Discord. Itu eksplisit untuk **bagian 2**.

## OVH vs Hostinger vs DigitalOcean — kenapa OVH VPS-1?

Perbandingan ini bukan benchmark performa mendalam; ini **keputusan praktis** untuk project pribadi dengan budget kecil.

| Provider         | Kesan singkat                              | Catatan untuk Hermes starter                                                  |
| ---------------- | ------------------------------------------ | ----------------------------------------------------------------------------- |
| **DigitalOcean** | UX rapi, dokumentasi enak, komunitas besar | Droplet $4–6/bln setara; sering jadi default tutorial                         |
| **Hostinger**    | Harga promosi menarik untuk pemula         | Pastikan plan benar-benar VPS (bukan shared hosting) dan region yang kamu mau |
| **OVH**          | Harga entry agresif, banyak lokasi DC      | **VPS-1** ~setara kebutuhan "agent kecil + gateway"                           |

Saya pilih **OVH VPS-1** karena:

1. **Harga bulanan rendah** untuk eksperimen jangka panjang (lihat order nyata di bawah).
2. **No commitment** — cocok kalau masih fase belajar; tidak terikat kontrak panjang.
3. **Ubuntu 24.04 LTS** tersedia di flow order — cocok untuk Python 3.11+ yang Hermes butuhkan nanti.
4. Region **Canada East (Beauharnois)** — cukup untuk latency yang wajar dari Indonesia untuk tugas agent (bukan game real-time).

DigitalOcean tetap opsi bagus kalau kamu sudah nyaman dengan ekosistem mereka. Hostinger masuk radar kalau promo dan spesifikasi VPS-nya pas. Untuk NOV-132, keputusannya **OVH**.

## Order OVH sampai VPS ready (langkah yang sudah saya lakukan)

Berikut alur yang saya ikuti — tanpa detail kartu kredit atau kredensial:

1. Buat / login akun OVH, masuk ke order **VPS**.
2. Pilih plan **VPS-1** (spesifikasi entry — cukup untuk tahap install Hermes + gateway ringan).
3. **Sistem operasi:** Ubuntu **24.04**.
4. **Komitmen:** no commitment (bulanan).
5. **Lokasi datacenter:** **Canada East — Beauharnois**.
6. Selesaikan pembayaran dan simpan nomor order.

**Order saya:** `#23055087`  
**Perkiraan biaya:** sekitar **$5.35/bulan** (sesuai ringkasan checkout OVH saat order; pajak/kurs bisa sedikit berbeda).

Setelah bayar, status VPS tidak selalu langsung **Ready**. Di kasus saya, dashboard menunjukkan fase **checking** — provisioning bisa memakan waktu, dan untuk order ini catatan realistisnya: **bisa sampai ~48 jam** sebelum VPS benar-benar siap SSH. Jadi waktu nunggu itu bukan bug; itu bagian normalnya cloud murah.

**Titik berhenti bagian 1:** VPS sudah dibeli, OS dan region sudah dipilih, status masih menunggu OVH — **belum** ada `ssh root@...`, belum hardening, belum install Hermes.

## Persiapan paralel (selagi VPS checking)

Jangan buang waktu 48 jam hanya melihat spinner di panel OVH. Dua hal ini aman dikerjakan paralel:

### 1. DeepSeek API key

1. Buka [platform.deepseek.com](https://platform.deepseek.com).
2. Buat akun / login.
3. Buat **API key** di dashboard developer.
4. Simpan key di password manager atau file `.env` lokal — **jangan** commit ke Git, **jangan** paste di blog atau Discord.

Key ini baru akan dipakai Hermes di bagian 2 (`hermes model` / env di server). Di bagian 1 cukup pastikan key **ada** dan **aman**.

### 2. Rencana gateway: Discord (bukan Telegram)

Dokumentasi Hermes banyak contoh Telegram, tapi untuk setup saya **gateway nanti Discord**. Artinya di bagian berikutnya kita akan:

- Buat aplikasi/bot di Discord Developer Portal.
- Simpan bot token dengan cara yang sama seperti API key (rahasia, hanya di server).
- Jalankan **satu proses gateway** Hermes yang menghubungkan model DeepSeek ke channel Discord.

Belum perlu token Discord hari ini kalau VPS belum ready — yang penting keputusannya sudah fix: **Discord**, supaya tidak bolak-balik ganti channel.
