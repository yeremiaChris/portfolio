## The one-line pitch

**Hermes Agent** is open-source software that runs on a machine you control, talks to a model API, uses tools, remembers context, and can improve reusable “skills” over time. **Part 1** is the full “it works in Discord” milestone. **Part 2** is making it boringly safe to leave on 24/7.

## What is Hermes Agent — and how is it not “just a chatbot”?

A browser chatbot is a tab: you type, it replies, the session ends. An **agent** is closer to a small employee with permissions.

**Hermes Agent** ([Nous Research](https://github.com/NousResearch/hermes-agent)) can:

- **Run tools** — read files, run commands, schedule jobs, and more (within limits you configure).
- **Remember** across sessions — search old conversations instead of starting from zero every morning.
- **Accumulate skills** — reusable instructions the project can refine over time (the docs call this a self-improving loop).

|         | Classic chatbot        | Hermes-style agent                        |
| ------- | ---------------------- | ----------------------------------------- |
| Memory  | Mostly “this tab only” | Can recall prior sessions and saved notes |
| Actions | Answers text           | Can act on a server (tools)               |
| Growth  | Static FAQ             | Can add or tune skills from experience    |

Hermes also **does not lock you to one model vendor**. For this build I use the **[DeepSeek API](https://platform.deepseek.com)**. The VPS is the **body**; the API is the **brain** you can swap later.

## How Hermes landed on the Biznet VM (high level, no fake logs)

I followed the **[official Hermes Agent docs](https://hermes-agent.nousresearch.com/docs/)** — two supported paths, same idea: install software, run setup, point at a model, start the **gateway**.

After setup, the **Hermes TUI** is the “this is real” moment — not a bland API wrapper. On my VM it shows **Hermes Agent v0.21.5**, model **`deepseek-v4-flash`**, and a live summary of **21 tools** and **58 skills** (browser, code execution, Discord admin, GitHub, and more). Window chrome is cropped in the screenshot so no host/IP leaks into a public post.

![Hermes Agent TUI welcome screen — v0.21.5, deepseek-v4-flash, tools and skills overview](/blog/hermes-agent-part-1/hermes-cli-tui.png)

### Path A — install script (what the docs recommend on Linux)

1. SSH into the Ubuntu VM (placeholder IP above).
2. Run the published installer (from the docs):  
   `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash`
3. Run **`hermes setup`** (or the interactive setup the installer walks you through).
4. Put **secrets in `.env`** on the server — DeepSeek API key, Discord bot token — not in Git. The docs stress provider keys live in env, not in committed config.
5. Point Hermes at DeepSeek (provider env / `hermes model` flow per docs).
6. Configure Discord: application token plus **allowed users** (Hermes defaults to deny strangers — keep it that way).
7. Start the gateway: **`hermes gateway setup`**, then run the gateway process (docs: `hermes gateway` / status checks with **`hermes gateway status`**).

I am **not** pasting my terminal session here. If you are following along, treat the doc pages as source of truth for exact flags this week.

### Path B — Docker (same lifecycle, containerized)

Docs also document a Docker image (`nousresearch/hermes-agent`): run **setup** once with a volume for `~/.hermes`, then run **gateway** supervised in the container with that same volume. Good when you want a clean rollback boundary on a small VPS.

## What comes in part 2

The agent already answers in Discord. The next post focuses on **production hygiene**, not first boot:

1. **Harden the Biznet VM** — keys-only SSH, updates, least-privilege user.
2. **Lock down the gateway** — explicit allowlists, no `*_ALLOW_ALL_USERS` shortcuts.
3. **Cron and skills** — one real scheduled routine and a documented skills folder.
4. **Observability** — what to log when an agent can run tools.
