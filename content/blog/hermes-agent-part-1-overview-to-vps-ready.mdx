I am documenting a **Hermes Agent** build on yeremiachris.com in public. This is **part 1**.

By the end of this post you should understand what an agent is (in plain language), why I picked a small stack, and what infrastructure is already in place. What you will **not** get here yet: a step-by-step Hermes install, SSH hardening as a finished checklist, or fake terminal output. Part 2 covers SSH, installing Hermes, putting DeepSeek on the server, and turning on the **Hermes** Discord gateway.

If you are a recruiter skimming for signal: I am not just “using ChatGPT.” I am standing up a **self-hosted agent** with a real VPS, a real chat surface, and a deliberate security mindset. If you are an engineer new to agents: I wrote this the way I wish someone had explained it to me — short sections, one idea at a time.

## The one-line pitch

**Hermes Agent** is open-source software that runs on a machine you control, talks to a model API, uses tools, remembers context, and can improve reusable “skills” over time. **Part 1** is about choosing that machine and the front door (Discord). **Part 2** is where the agent brain actually moves in.

## What is Hermes Agent — and how is it not “just a chatbot”?

A browser chatbot is a tab: you type, it replies, the session ends. An **agent** is closer to a small employee with permissions.

**Hermes Agent** ([Nous Research](https://github.com/NousResearch/hermes-agent)) can:

- **Run tools** — read files, run commands, schedule jobs, and more (within limits you configure later).
- **Remember** across sessions — search old conversations instead of starting from zero every morning.
- **Accumulate skills** — reusable instructions the project can refine over time (the docs call this a self-improving loop).

Picture two front desks at the same company.

|         | Classic chatbot        | Hermes-style agent                        |
| ------- | ---------------------- | ----------------------------------------- |
| Memory  | Mostly “this tab only” | Can recall prior sessions and saved notes |
| Actions | Answers text           | Can act on a server (tools)               |
| Growth  | Static FAQ             | Can add or tune skills from experience    |

That “self-improving” label is not magic. It means Hermes is designed to **capture what worked**, store it as a skill, and reuse it — instead of you re-prompting the same deploy checklist every week.

Hermes also **does not lock you to one model vendor**. OpenRouter, OpenAI, your own endpoint — swap with configuration. For this series I am using the **[DeepSeek API](https://platform.deepseek.com)** for cost and simplicity. The VPS is only the **body**; the API is the **brain** you can change without rebuilding the server.

## What would I actually use it for?

I am not claiming production workloads on day one. These are the **use cases that motivated the project**:

- **Always-on assistant** on a VPS instead of keeping my laptop awake 24/7.
- **One gateway, many surfaces** — Hermes supports many channels; this build targets **Discord** (not Telegram), because that is where I already collaborate.
- **Scheduled routines** — daily digests, backups, or audits via Hermes cron (part 2+).
- **Delegation** — subagents for parallel tasks when a job splits cleanly.
- **Portable skills** — aligned with [agentskills.io](https://agentskills.io) so work compounds instead of resetting every Monday.

Part 1 stops once the **home** (VPS) and **front door prep** (Discord application) exist. The agent runtime itself is the next chapter.

## Stack: separate brain and body

| Layer                               | Choice                                                                | Why it fits a first build                                                                         |

| Model                               | DeepSeek API                                                          | Competitive pricing; familiar HTTP API; easy to point Hermes at later                             |
| Compute                             | **Biznet GIO Cloud** — compute **Hermes**, plan **MS 4.2 / NEO LITE** | Indonesian provider, monthly billing in IDR; VM named after the project                           |

Why not serverless on day one? Hermes supports Docker, SSH backends, Modal, and more. A modest **monthly VM** is the easiest place to **learn the moving parts** without surprise bills. You can always add serverless or a bigger box once you know your RAM and tool footprint.

## Picking a VPS: what I compared, what I bought

This is a **budget and learning** decision, not a benchmark medal. Early notes in this series mentioned overseas options (for example **OVH** VPS-1 in Canada or **DigitalOcean** droplets). Those are still fine defaults in tutorials. **What I actually run today** is on **Biznet GIO Cloud** in Indonesia — closer to home, IDR billing, and a control panel I can read without timezone math.

| Provider             | Vibe                                                | Hermes starter note                                              |
| -------------------- | --------------------------------------------------- | ---------------------------------------------------------------- |
| **DigitalOcean**     | Polished UI, excellent tutorials                    | ~$4–6/mo droplets; common in English blog posts                  |
| **Hostinger**        | Aggressive promos                                   | Confirm it is real VPS, not shared hosting                       |
| **OVH**              | Strong entry price in EUR/USD                       | Worth a look if you want EU/NA regions; I considered it early on |
| **Biznet GIO Cloud** | Indonesian cloud (compute, storage, billing in IDR) | **NEO Lite** tier — active compute for this project              |

I provisioned **Biznet GIO** compute named **Hermes** on plan **MS 4.2 / NEO LITE** because:

1. **Local provider** — support and invoices in a context I already use.
2. **Monthly cycle** — renew or resize without a long contract (see dates below).
3. **Clear “Active” status** in the dashboard — easy to show learning-in-public progress.
4. **Enough headroom for part 2** — install Hermes, gateway, and light tooling on a small VM before I optimize.

## Parallel work while the VM was coming online

Setup time is a good window for keys and Discord — work that does not require the disk image to be perfect yet.

3. Store it in a password manager or a local `.env` — **never** in Git, Discord, or a blog post.

Hermes will consume this on the server in part 2. Part 1 success = key exists and stays secret.

### Discord: two different paths (do not mix them up)

I committed to **Discord** over Telegram for this build. Hermes docs show Telegram often; that is fine — it is just not **this** series.

**Path A — Hermes Discord gateway (part 2):**

- Create a Discord application and bot in the [Developer Portal](https://discord.com/developers/applications).
- Invite the bot to your server with the right OAuth scopes.
- Configure allowed users (Hermes defaults to **deny** strangers — good).
- Run `hermes gateway` on the VPS so **Hermes** owns the conversation loop and tools.

**Path B — what I already have live today (not Hermes):**

- Discord application **`yeremiachris`** is online on my server.
- Channels such as **#ai** work; **DMs work too**.
- Some messages may flow through **Composio** (for example a Grok Bot or webhook-style posting). That is a **separate integration** — useful for experiments, but it is **not** the Hermes gateway and does not give you Hermes tools, skills, or cron on the VPS.

Keeping that distinction straight matters for recruiters and teammates: **Discord online ≠ Hermes deployed.**

High-level Discord prep I did in parallel (no tokens in this post):

1. Developer Portal → New Application → Bot user enabled.
2. Copy the bot token **once** into a secret store (server-side only).
3. Generate an invite URL (applications → OAuth2 → URL Generator) with bot scope + permissions for the channels you need.
4. Create or reuse channels (e.g. **#ai**) and verify the bot can read/send.
5. Test DM allowlisting mindset early — only people you trust should talk to an agent with tools.
