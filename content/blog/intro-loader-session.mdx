The overlay on `/` is **not a loading gate**. The page is already there. Home can play a short branded cover, then it exits while content underneath stays at its final painted state.

**One-sentence answer:** `sessionStorage` remembers the intro for **this tab** only. Close the tab and the session ends, so it plays again on the next visit to `/`. An inline script in the root layout sets `data-intro` on `<html>` before first paint; CSS drives the cover exit. There is no React store and no hero re-animation after the cover leaves.

## What you actually see

`IntroCover` is the first meaningful node in `<body>` (right after the inline script and critical intro CSS), so streaming cannot paint the header or hero above the cover on first visit.

| You do                                                                    | Intro? |
| ------------------------------------------------------------------------- | ------ |
| First visit to `/` in this tab (desktop, motion allowed, fast connection) | Yes    |
| Refresh, or `/about` → `/` in the **same** tab                            | No     |
| Close the tab, open `/` again                                             | Yes    |
| Any non-home route (`/blog`, `/about`, …)                                 | No     |
| Mobile viewport (≤767px)                                                  | No     |
| `prefers-reduced-motion`                                                  | No     |
| Save-data or slow 2g/3g                                                   | No     |

That is **choreography**, not progress tied to fonts or data.

## `sessionStorage`, not `localStorage`

The browser stores `intro-seen = 1` until **that tab's session ends**. Refresh keeps it. A new tab or a closed tab does not.

`localStorage` would remember forever — wrong for a calling-card intro you still want on the next visit.

When the sequence completes (or the user skips with click / Escape / Enter / Space), the inline script writes `intro-seen` and sets `html[data-intro="seen"]`. CSS hides `[data-intro-cover]`. Helpers and tests live in `lib/intro.ts`.

## Pre-paint script + `data-intro`

React does not choose skip vs play on first paint. A minified inline script in `app/layout.tsx` runs immediately and sets `data-intro` to `playing` or `seen`:

- **Seen:** existing session flag, reduced motion, mobile width, slow connection, or pathname not `/`
- **Playing:** first desktop visit to `/` only; a timeout flips to `seen` after the CSS exit duration

Critical CSS in the same layout hides the cover when `data-intro="seen"` or under the mobile / reduced-motion media queries, so return visits do not flash the overlay.

Hydration does not remount the cover or rewrite `data-intro`. The server-rendered cover stays in the tree; only the script mutates the attribute once per load.

## Cover exit without Motion

The overlay is a fixed full-viewport layer (`[data-intro-cover]`) with staged CSS animation (mark → name → role → bar → exit). No `AnimatePresence`, no `motion` on the intro path.

When `data-intro` becomes `seen`, the cover is removed from layout via `display: none` in CSS after the exit finishes — not mid-keyframes via React unmount.

## Hero stays at final state (no second entrance)

Previously the hero also ran CSS **fade-up** entrances after the cover left, which felt like the intro playing twice and could blink when `html[data-hydrated]` stopped animations.

Now hero copy, CTAs, and name stay **opacity 1** with **no transform** under the cover. When the cover exits, nothing underneath animates in again. When the intro is skipped, the same final state is shown — no visible → hidden → visible cycle.

LCP can still target the hero heading on first paint because it is not gated on the overlay finishing.

## Layout split

| Piece                         | Role                                                                                          |
| ----------------------------- | --------------------------------------------------------------------------------------------- |
| `lib/intro.ts`                | Timings, storage key, bootstrap script builder, skip helpers (Vitest)                         |
| `components/intro/IntroCover` | Server markup for `[data-intro-cover]`                                                        |
| `app/layout.tsx`              | Script, critical CSS, cover before header/main                                                |
| Home page                     | No intro gate component; cover is global but **plays** only on `/` via pathname in the script |

Do not set `data-intro="seen"` before the CSS exit window if you want the fade to complete; the timeout in the bootstrap script matches the exit duration.
