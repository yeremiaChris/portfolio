Architectural Executive Summary

When processing over 50,000 multi-destination logistics shipments per day, interaction latency is not a vanity metric—it dictates operational throughput. Our initial logistics dashboard suffered from interaction to next paint (INP) spikes upwards of 268ms during concurrent multi-carrier pricing recalculations. By decoupling state derivation into an isolated Web Worker actor loop, adopting OffscreenCanvas barcode streams, and enforcing strict micro-task scheduling with scheduler.yield(), we crushed INP down to an ultra-responsive 34ms (P95) with zero dropped user keystrokes.

01 //

The Bottleneck in Multi-Courier Matrix Calculations

In high-volume B2B logistics aggregators, a single operational view presents live tables containing hundreds of shipments. When an operator adjusts a parcel parameter (such as cubing dimensions, hazardous material flags, or origin postal zones), the system immediately triggers:

  • arrow_right 15+ Carrier Rate Lookups: Instant pricing algorithms factoring in volumetric discount thresholds, fuel surcharges, and SLA guarantees (JNE, SiCepat, J&T, NinjaVan, POS Indonesia).
  • arrow_right High-Density Code128 / QR Rendering: Dynamic generation of standard shipping barcode vectors rendered across tens of tabular rows simultaneously.
  • arrow_right Virtual DOM Thrashing: Traditional React reconciliation running massive differential trees across 200+ rendered nodes, starving the browser's compositor thread.

03 //

Offloading to Web Workers with Zero Serialization Overhead

Standard postMessage() payloads often introduce hidden serialization serialization penalties when transferring thousands of objects. We implemented a memory-efficient zero-copy array buffer protocol utilizing SharedArrayBuffer where supported, with fallback to structured cloning via Transferable Objects.

workers/logistics-matrix.worker.ts 
1import { CarrierEngine } from '@kiriminaja/carrier-core';
2import { chunkTask } from '@/lib/scheduler';
3
4// Offload heavy pricing recalculations away from DOM compositor
5self.onmessage = async (event: MessageEvent<CalculationPayload>) => {
6  const { waybills, carrierMatrix, rateConfig } = event.data;
7  const calculatedRates: CalculatedRateResult[] = [];
8
9  // Enforce 8ms cooperative time-slicing within Worker
10  await chunkTask(waybills, async (waybill) => {
11    const quote = CarrierEngine.evaluateRates({
12      weightGrams: waybill.billableWeight,
13      originPostal: waybill.originCode,
14      destinationPostal: waybill.destCode,
15      matrix: carrierMatrix,
16    });
17    calculatedRates.push({ id: waybill.id, quote });
18  }, { sliceBudgetMs: 8 });
19
20  // Zero-copy Transferable ArrayBuffer back to UI main-thread
21  const serializedBuffer = packToBinary(calculatedRates);
22  self.postMessage(serializedBuffer, [serializedBuffer.buffer]);
23};
04 //

Deterministic State & Offscreen Canvas Rendering

Beyond calculating freight rates, high-density waybill printing required generating thousands of Code128 barcodes. Injecting inline SVG elements bloated the DOM tree to 12,000+ nodes, turning simple table row selections into 120ms recalculation traps.

center_focus_weak OffscreenCanvas Pipes

Barcodes are now pre-rasterized inside background worker instances using standard OffscreenCanvas, transferring raw ImageBitmaps without triggering main thread reflows.

hourglass_empty scheduler.yield() Integration

We polyfilled the progressive Chrome Scheduling API (scheduler.yield()). Heavy batch renders cooperatively yield execution to the browser event loop every 12ms.
